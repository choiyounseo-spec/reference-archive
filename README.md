# Reference Archive (설치형 웹앱)

이미지+메모 아카이브, 캘린더, 일기장, 퀘스트로그, 행동원칙까지 한 앱 안에서 쓰는 개인용 오프라인 웹앱입니다.
데이터는 서버로 전송되지 않고 브라우저 저장소(기기 안)에만 저장됩니다.

## 이번 업데이트로 추가된 것

- **캘린더/아카이브**: 하루에 메모를 여러 개 쓸 수 있어요. 그 중 하나가 "대표 메모"로 캘린더에 표시되고, 나머지는 날짜는 유지된 채 캘린더에는 안 보여요 (아카이브 탭이나 날짜 클릭 시 목록에서 전체 확인 가능).
- **일기장**: 캘린더/아카이브와는 독립된 별도 데이터예요. 연도 → 월별로 접고 펼치는 리스트뷰, 작성 시 INPUT/OUTPUT 키워드, 날씨·체온·수면질·컨디션·기분, 4가지 회고 질문을 입력해요.
- **퀘스트로그**: 예전에 만들어드린 PIXEL QUEST LOG를 이 앱의 탭 안에 그대로 넣었어요 (내부적으로는 `pixel-quest-log.html`을 불러오는 방식이라, 그 파일도 반드시 같은 폴더에 있어야 해요). 각자 자기 저장 방식을 그대로 씁니다.
- **행동원칙**: 캘린더/아카이브와 독립된 별도 페이지예요. 자유 줄글을 적으면 세리프체로 정돈되어 보이고, 편집 버튼으로 언제든 수정할 수 있어요.
- **백업**: ⋯ 메뉴의 내보내기/가져오기가 이제 아카이브+일기장+원칙을 한 파일로 같이 담아요. (퀘스트로그는 자체 저장 방식이라 이 백업에는 포함되지 않아요.)

## 업데이트해도 예전 화면이 계속 보일 때 (캐시 문제)

이 앱은 오프라인에서도 열리도록 서비스워커가 파일을 기기에 캐시해둬요. 그런데 예전 버전 `sw.js`는 "캐시에 있으면 무조건 캐시부터" 보여주는 방식이라, 서버에 새 파일을 올려도 브라우저가 계속 예전 버전을 보여주는 경우가 있었어요. **이번 버전부터는 HTML 파일(`index.html`, `pixel-quest-log.html`)은 온라인이면 항상 서버의 최신 파일을 먼저 받아오고, 인터넷이 끊겼을 때만 캐시를 대신 쓰도록 바꿨어요.** 앞으로는 파일을 새로 올리면 새로고침만으로 최신 버전이 반영돼요.

다만 **이미 예전 sw.js가 설치되어 있던 기기(폰/PC)** 는 새 sw.js로 자동 교체되기까지 한 번의 "정리"가 필요할 수 있어요. 아래 중 편한 방법으로 한 번만 해주세요.

- **가장 간단한 방법**: 강력 새로고침 — PC는 `Ctrl+Shift+R`(Mac은 `Cmd+Shift+R`)을 그 사이트에서 2번 정도 눌러주세요.
- **확실한 방법 (PC, Chrome/Edge)**: F12(개발자 도구) → **Application 탭 → Service Workers** → 해당 사이트 항목 옆 **Unregister** 클릭 → 페이지 새로고침
- **폰에서 안 바뀔 때**: 설치했던 아이콘을 삭제하고, 브라우저에서 사이트 접속 → 새로고침 → 다시 홈 화면에 추가

이후로는 파일을 업데이트할 때마다 이 과정을 반복할 필요 없이 새로고침만 하면 최신 버전이 보여요.

## 1. GitHub Pages로 배포하기 (무료, 5분)

1. GitHub에서 새 저장소를 만듭니다. (예: `reference-archive`, Public)
2. 이 폴더 안의 6개 파일을 저장소에 **그대로, 같은 폴더 레벨로** 업로드합니다.
   - `index.html`, `manifest.json`, `sw.js`, `icon-192.png`, `icon-512.png`, `pixel-quest-log.html`
   - ⚠️ `pixel-quest-log.html`이 `index.html`과 다른 폴더에 있으면 퀘스트로그 탭이 비어 보여요.
3. 저장소의 **Settings → Pages**로 이동합니다.
4. **Source**를 `Deploy from a branch` → 브랜치는 `main`, 폴더는 `/ (root)`로 설정하고 저장합니다.
5. 1~2분 뒤 `https://[깃허브아이디].github.io/reference-archive/` 주소가 생깁니다.

## 2. PC에 앱처럼 설치하기 (Chrome / Edge)

**꼭 기억할 것: 설치 버튼은 위 1번처럼 `https://`로 실제 호스팅된 주소에서만 나타나요.**
`index.html` 파일을 로컬에서 더블클릭해서 열면(`file://...`) 브라우저가 보안상 설치를 허용하지 않아서 버튼 자체가 없어요. 안 보이셨던 이유는 대부분 이것 때문이에요.

호스팅된 주소로 접속한 뒤에도 브라우저 버전에 따라 설치 버튼 위치가 달라요. 아래 순서로 확인해보세요.

1. 주소창 오른쪽 끝을 봅니다 — 모니터/⊕ 모양의 작은 설치 아이콘이 있으면 클릭
2. 안 보이면 브라우저 오른쪽 위 **⋮ (점 3개) 메뉴**를 클릭 → **"앱 설치"** 또는 **"[이 사이트]을(를) 앱으로 설치"** / **"Save and Share → Install page as app"** 항목을 찾아 클릭
3. 그래도 안 보이면, 페이지가 완전히 로드된 뒤(스피너가 끝난 뒤) 새로고침을 한 번 해보세요 — 설치 조건 판정이 로드 완료 후에 이뤄지는 경우가 있어요
4. 그래도 안 뜨면 설정 진단: 주소창에 `chrome://` 또는 Edge는 `edge://`가 아니라 **F12(개발자 도구) → Application 탭 → Manifest** 항목을 열어 오류가 없는지, **Service Workers** 항목에 `sw.js`가 정상 등록되어 있는지 확인해주세요. 여기 빨간 오류가 있으면 그게 원인이에요.

설치되면 실제 앱처럼 아이콘이 생기고 브라우저 주소창 없이 독립 창으로 실행됩니다.

## 3. 폰에 설치하기

- **iPhone (Safari)**: 주소 접속 → 공유 버튼 → **홈 화면에 추가**
- **Android (Chrome)**: 주소 접속 → 우측 상단 ⋮ 메뉴 → **홈 화면에 추가** (또는 자동으로 뜨는 설치 배너)

## 4. 여러 기기에서 쓰기 (수동 백업/복원)

기기별로 데이터가 따로 저장돼요(자동 동기화 없음). 다른 기기로 옮기려면:

1. 기존 기기에서 **⋯ 메뉴 → 백업 내보내기** → JSON 파일 다운로드
2. 파일을 새 기기로 이동 (에어드롭, 카카오톡 '나에게 보내기', 클라우드 드라이브 등)
3. 새 기기에서 **⋯ 메뉴 → 백업 가져오기** → 그 파일 선택

같은 id를 가진 기록은 덮어쓰는 방식이라, 정기적으로 내보내기 해두면 안전한 백업본으로도 쓸 수 있어요.
(퀘스트로그 데이터는 이 백업에 포함되지 않아요 — 필요하면 요청해주시면 별도 내보내기 기능을 추가해드릴게요.)

## 5. 로컬에서 바로 테스트하기

더블클릭으로 열면 대부분 기능은 되지만, 서비스워커·PWA 설치·(같은 이유로) 일부 아이콘 표시가 제한됩니다.
정확히 테스트하려면 이 폴더에서:

```bash
python3 -m http.server 8000
```

후 `http://localhost:8000` 접속하세요. `localhost`는 `file://`과 달리 보안 조건을 충족해서 설치 버튼도 정상적으로 나타나요.

## 파일 구성

```
index.html            메인 앱 — 캘린더 / 아카이브 / 일기장 / 퀘스트로그 / 원칙
pixel-quest-log.html  퀘스트로그 (index.html의 iframe으로 불러옴, 단독 실행도 가능)
manifest.json         PWA 설치 메타데이터
sw.js                 오프라인 캐싱용 서비스워커
icon-192.png          앱 아이콘 (작은 크기)
icon-512.png          앱 아이콘 (큰 크기)
```
