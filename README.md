# Reference Archive (설치형 웹앱)

이미지 + 짧은 메모를 날짜별로 기록하고, 캘린더 뷰 / 아카이브(검색·태그) 뷰로 찾아보는 개인용 오프라인 웹앱입니다.
데이터는 서버로 전송되지 않고 브라우저의 IndexedDB에 기기 안에만 저장됩니다.

## 1. GitHub Pages로 배포하기 (무료, 5분)

1. GitHub에서 새 저장소를 만듭니다. (예: `reference-archive`, Public)
2. 이 폴더 안의 5개 파일을 저장소에 그대로 업로드합니다.
   - `index.html`, `manifest.json`, `sw.js`, `icon-192.png`, `icon-512.png`
3. 저장소의 **Settings → Pages**로 이동합니다.
4. **Source**를 `Deploy from a branch` → 브랜치는 `main`, 폴더는 `/ (root)`로 설정하고 저장합니다.
5. 1~2분 뒤 `https://[깃허브아이디].github.io/reference-archive/` 주소가 생깁니다.

## 2. 폰에 "앱처럼" 설치하기

- **iPhone (Safari)**: 위 주소 접속 → 공유 버튼 → **홈 화면에 추가**
- **Android (Chrome)**: 위 주소 접속 → 우측 상단 메뉴(⋮) → **홈 화면에 추가** / 또는 자동으로 뜨는 설치 배너 사용
- **PC (Chrome/Edge)**: 주소창 오른쪽의 설치 아이콘 클릭

설치하면 아이콘이 생기고, 브라우저 UI 없이 전체화면 앱처럼 실행됩니다. 한 번 방문한 뒤에는 오프라인에서도 열립니다.

## 3. 여러 기기에서 쓰기 (수동 백업/복원)

이 버전은 기기별로 데이터가 따로 저장됩니다(자동 동기화 없음). 다른 기기로 데이터를 옮기려면:

1. 기존 기기에서 우측 상단 **⋯ 메뉴 → 백업 내보내기** → JSON 파일이 다운로드됨
2. 그 파일을 새 기기로 옮김 (에어드롭, 카카오톡 '나에게 보내기', 클라우드 드라이브 등)
3. 새 기기의 앱에서 **⋯ 메뉴 → 백업 가져오기** → 방금 옮긴 파일 선택

가져오기는 같은 id를 가진 기록을 덮어쓰는 방식이라, 정기적으로 내보내기 해두면 안전한 백업본으로도 쓸 수 있습니다.

## 4. 로컬에서 바로 테스트하기

`index.html`을 더블클릭해서 열면 대부분 기능이 동작하지만, 서비스워커(오프라인 캐싱)와 PWA 설치는 `file://`에서는 제한됩니다.
정확히 테스트하려면 이 폴더에서 아래 명령을 실행한 뒤 `http://localhost:8000`으로 접속하세요.

```bash
python3 -m http.server 8000
```

## 파일 구성

```
index.html      메인 앱 (UI + 로직, 프레임워크 의존성 없음)
manifest.json   PWA 설치 메타데이터
sw.js           오프라인 캐싱용 서비스워커
icon-192.png    앱 아이콘 (작은 크기)
icon-512.png    앱 아이콘 (큰 크기)
```
